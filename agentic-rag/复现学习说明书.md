## 七个大阶段

以下示例采用 DeepSeek 官方文档当前列出的 `deepseek-flash`。若账户可用模型不同，需要替换 `model`。不要把 API Key 写进 Python 文件。API 调用会产生实际用量。

### 1.1 加载配置，初始化并调用模型

#### 需要做什么

读取上一级目录中的 `.env`，创建模型对象，发送一个简单问题。先确认配置加载和模型连接成功。

将下面完整代码写入 `01_tool_call.py`：

```python
import os
from pathlib import Path

from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, SystemMessage

# __file__ 指当前 Python 文件；resolve() 得到它的绝对路径。
# 第一层 parent 是 agentic-rag，第二层 parent 是 dummies。
# 因此，无论终端从哪个目录运行，都能找到现有的 .env。
env_path = Path(__file__).resolve().parent.parent / ".env"
load_dotenv(env_path)

# ChatOpenAI 是兼容 OpenAI 聊天接口的适配器，也可以连接 DeepSeek。
# 显式传入密钥和地址，因为 DEEPSEEK_* 不会被自动当作 OPENAI_* 读取。
# 创建对象只是保存连接配置；真正发送请求发生在 invoke 时。
llm = ChatOpenAI(
    model="deepseek-flash",
    api_key=os.environ["DEEPSEEK_API_KEY"],
    base_url=os.environ["DEEPSEEK_BASE_URL"],
    temperature=0,
)

# SystemMessage 说明回答要求；HumanMessage 表示用户的问题。
# 消息列表的顺序就是本次提供给模型的对话顺序。
messages = [
    SystemMessage(content="你是一位编程老师，请用简体中文简短回答。"),
    HumanMessage(content="用一个例子解释什么是 RAG。"),
]

# invoke 发送请求并等待返回；返回值是 AIMessage，而不是普通字符串。
response = llm.invoke(messages)

# content 是回答内容；usage_metadata 是接口提供的用量信息。
# 某些兼容接口可能不提供完整的 usage_metadata。
print("返回类型：", type(response).__name__)
print("回答内容：", response.content)
print("用量信息：", response.usage_metadata)
```

#### 验证方法

运行文件，确认输出类型是 `AIMessage`，并且有一段回答。把系统消息改成“只用一句话回答”，再运行一次，观察输出变化。`temperature=0` 不保证每次输出完全相同。

#### 应该能解释

为什么 `ChatOpenAI` 可以连接 DeepSeek？创建模型对象与 `invoke` 有什么区别？为什么回答是一个对象？

### 1.2 定义一个工具，先在本地执行

#### 需要做什么

把“两个整数相乘”包装成 LangChain 工具。先自己调用它，确认工具正确，再交给模型。

保留 1.1 中的导入、配置加载和 `llm` 初始化；删除从 `messages = [...]` 开始的所有代码，换成下面代码：

```python
from langchain_core.tools import tool


# @tool 把普通 Python 函数包装成工具对象。
# 函数名成为默认工具名称；类型注解描述输入类型。
# 文档字符串会成为工具说明，供模型判断用途。
@tool
def multiply(a: int, b: int) -> int:
    """计算两个整数的乘积。

    Args:
        a: 第一个整数。
        b: 第二个整数。
    """
    # 这段 Python 运算由本地程序执行，不是由模型执行。
    return a * b


# 被 @tool 包装后，用 invoke 传入与参数名称对应的字典。
result = multiply.invoke({"a": 17, "b": 23})

print("工具名称：", multiply.name)
print("工具说明：", multiply.description)
print("输入结构：", multiply.args)
print("本地结果：", result)
```

#### 验证方法

运行后结果应该是 `391`，输入结构应包含 `a`、`b` 两个整数参数。本步骤没有调用 `llm.invoke`，因此不会发送聊天请求。

#### 应该能解释

工具说明和普通代码注释有什么区别？为什么参数要写类型注解？模型看得到工具用途和输入结构，并不意味着它能直接运行本地函数。

### 1.3 将工具绑定到模型

#### 需要做什么

让模型知道存在 `multiply` 工具。这里仅绑定工具，不发送请求，也不执行工具。

保留工具定义，删除 1.2 中从 `result = ...` 开始的代码，换成：

```python
# 把工具名称、说明和参数结构提供给模型的调用配置。
# bind_tools 返回一个新的可调用对象；原来的 llm 仍可使用。
# 它不会自动执行 multiply，也不会在这行发起模型请求。
llm_with_tools = llm.bind_tools([multiply])

print("工具已绑定，下一步将向模型发送问题。")
```

#### 验证方法

运行后没有报错。这一步只能证明本地绑定成功；服务端是否接受工具配置，需要在下一步通过真实调用确认。

#### 应该能解释

`multiply.invoke(...)` 是执行工具；`llm.bind_tools(...)` 是向模型声明工具。两者承担不同职责。

### 1.4 让模型发起工具调用，读取请求

#### 需要做什么

向绑定工具后的模型提问，查看它请求调用哪个工具、使用什么参数。此时还不执行模型请求的工具。

在 1.3 的 `llm_with_tools = ...` 后添加以下代码，可删除那条提示打印：

```python
messages = [
    SystemMessage(
        content="你是计算助手。涉及乘法时必须使用 multiply 工具，"
        "收到工具结果后再用简体中文回答。"
    ),
    HumanMessage(content="请使用工具计算 17 × 23。"),
]

# 返回的仍是 AIMessage，但它可能包含工具调用请求。
# 工具调用请求存放在 tool_calls 中，content 可能为空。
response = llm_with_tools.invoke(messages)

print("文字内容：", response.content)
print("工具调用请求：", response.tool_calls)

# 提示词表达了使用工具的要求，但模型行为仍需实际检查。
# 若它直接回答，暂停本教学流程，先检查模型及其工具调用支持。
if not response.tool_calls:
    raise RuntimeError("模型没有请求调用工具，请检查模型支持和提示词。")

for call in response.tool_calls:
    # LangChain 将服务端返回的工具调用统一为字典结构。
    print("工具名称：", call["name"])
    print("工具参数：", call["args"])
    print("调用标识：", call["id"])
```

#### 验证方法

应看到工具名称 `multiply`、参数 `a=17` 和 `b=23`，以及非空调用标识。调用标识由接口返回，具体值每次可能不同。

这一步不是看模型有没有回答 `391`，而是看它有没有产生正确的工具调用请求。

#### 应该能解释

`tool_calls` 表达的是“请程序执行这些操作”。模型生成参数，程序决定如何执行。模型发起工具调用时，为什么 `content` 可能为空？

### 1.5 执行工具，并把结果放入消息历史

#### 需要做什么

读取模型请求，找到对应本地工具并执行。把结果转换为 `ToolMessage`，通过 `tool_call_id` 与原请求关联。

保留 1.4 的代码，在文件末尾添加：

```python
from langchain_core.messages import ToolMessage

# 必须先保存发起工具调用的 AIMessage。
# 下一次请求时，模型才能看到“我请求了什么工具”。
messages.append(response)

# 名称映射把模型返回的工具名称连接到本地工具对象。
# 本例只有一个工具；后续增加检索工具时使用同样的思路。
tools_by_name = {multiply.name: multiply}

# 一条 AIMessage 可以请求多个工具，逐个执行并返回结果。
for call in response.tool_calls:
    selected_tool = tools_by_name[call["name"]]
    result = selected_tool.invoke(call["args"])

    # ToolMessage 是提供给模型的工具结果消息。
    # content 使用字符串；tool_call_id 必须对应原工具调用的 id。
    tool_message = ToolMessage(
        content=str(result),
        tool_call_id=call["id"],
    )
    messages.append(tool_message)
    print("实际工具结果：", result)

# 查看消息角色顺序，确认请求和结果都已保存。
print("消息顺序：", [message.type for message in messages])
```

#### 验证方法

工具结果应该是 `391`。只有一个工具调用时，消息顺序应该是：`system → human → ai → tool`。

最后两条消息的对应关系是：AIMessage 中某个工具请求的 `id`，等于 ToolMessage 的 `tool_call_id`。

#### 应该能解释

为什么不能只把 `391` 当成一条 HumanMessage？为什么不能删除发起工具调用的 AIMessage？多个工具结果如何对应各自请求？

### 1.6 将完整历史交回模型，取得最终回答

#### 需要做什么

把包含工具请求和结果的消息列表发送给模型，让模型根据真实计算结果回答。

在 1.5 的末尾添加：

```python
# 这次使用没有绑定工具的 llm，让模型整理已有结果。
# 对本例这种只需一次乘法的任务，不必继续请求工具。
# 工具请求与工具结果已经在 messages 中，仍会被一起发送。
final_response = llm.invoke(messages)

print("最终回答：", final_response.content)

# 保存最终回答，便于观察一次完整交互的消息结构。
messages.append(final_response)
print("完整消息顺序：", [message.type for message in messages])
```

#### 验证方法

最终回答应包含正确结果 `391`。一个工具调用时，完整顺序为：`system → human → ai → tool → ai`。

你完成的流程是：

```text
用户提出问题
    ↓
模型返回工具名称和参数
    ↓
Python 程序执行工具
    ↓
程序将结果包装成 ToolMessage
    ↓
模型根据工具结果生成最终回答
```

这是一次工具调用闭环，还不是支持多轮工具决策的通用 Agent。第 4 阶段将用 LangGraph 条件路由实现“只要还有工具调用就继续执行，否则结束”。

## 第 1 阶段完整代码：用于核对

以下代码独立完整。完成六个小步骤后，可以用它核对自己的 `01_tool_call.py`，不要追加到已有文件末尾。

```python
import os
from pathlib import Path

from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, SystemMessage, ToolMessage
from langchain_core.tools import tool

# 1. 找到 dummies/.env；路径相对于代码文件，不依赖终端当前目录。
env_path = Path(__file__).resolve().parent.parent / ".env"
load_dotenv(env_path)

# 显式读取现有 DeepSeek 配置；构造对象本身不会发送聊天请求。
llm = ChatOpenAI(
    model="deepseek-flash",
    api_key=os.environ["DEEPSEEK_API_KEY"],
    base_url=os.environ["DEEPSEEK_BASE_URL"],
    temperature=0,
)


# 2. 将函数包装成工具：名称、说明和类型注解供模型理解。
@tool
def multiply(a: int, b: int) -> int:
    """计算两个整数的乘积。

    Args:
        a: 第一个整数。
        b: 第二个整数。
    """
    # 实际计算发生在本地 Python 程序中。
    return a * b


# 3. 声明可用工具；不会自动调用本地函数。
llm_with_tools = llm.bind_tools([multiply])

messages = [
    SystemMessage(
        content="你是计算助手。涉及乘法时必须使用 multiply 工具，"
        "收到工具结果后再用简体中文回答。"
    ),
    HumanMessage(content="请使用工具计算 17 × 23。"),
]

# 4. 第一次模型请求：取得工具调用指令。
response = llm_with_tools.invoke(messages)
print("模型请求：", response.tool_calls)

if not response.tool_calls:
    # 教学目标是观察工具调用，直接回答不能证明这个目标已经达成。
    raise RuntimeError("模型没有请求调用工具，请检查模型支持和提示词。")

# 5. 保存模型请求，再执行每个工具并追加对应结果。
messages.append(response)
tools_by_name = {multiply.name: multiply}

for call in response.tool_calls:
    # name 确定执行哪个工具，args 确定传入什么参数。
    selected_tool = tools_by_name[call["name"]]
    result = selected_tool.invoke(call["args"])
    print("工具执行：", call["name"], call["args"], "→", result)

    messages.append(
        ToolMessage(
            content=str(result),
            # id 是关联工具请求与结果的关键，不要自行编造或替换。
            tool_call_id=call["id"],
        )
    )

# 6. 第二次模型请求：发送已有工具结果，让模型生成最终回答。
# 使用未绑定工具的 llm，在这个单步练习中结束工具决策。
final_response = llm.invoke(messages)
messages.append(final_response)

print("最终回答：", final_response.content)
print("完整消息顺序：", [message.type for message in messages])
```

## 常见问题

| 现象 | 应该检查什么 |
| --- | --- |
| `KeyError: DEEPSEEK_API_KEY` | 文件是否位于 agentic-rag 中；上一级 `.env` 是否包含该变量 |
| `ModuleNotFoundError` | 是否已激活 lang；当前运行的 Python 是否属于这个环境 |
| 401 或鉴权失败 | 密钥是否有效，变量是否有值；不要打印或分享完整密钥 |
| 余额不足、限流 | 根据服务返回检查账户余额或请求限制 |
| 模型不存在 | 按账户和官方文档确认当前可用模型名 |
| `tool_calls` 为空 | 模型是否支持工具调用、工具说明与提示词是否清楚；不能只凭数字答案判断成功 |
| 工具消息配对错误 | AIMessage 是否先保存，每个 tool_call 是否都有匹配 id 的 ToolMessage |
| 网络或证书错误 | 根据实际报错检查网络、代理和证书配置，不要通过关闭证书校验绕过问题 |
