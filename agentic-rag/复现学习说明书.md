### 1.2 定义检索工具的数据契约

#### 需要做什么

直接采用与原项目对应的两个工具名：`search_child_chunks` 和 `retrieve_parent_chunks`。先固定返回协议：搜索返回子块、父块 ID 和来源；父块读取返回完整内容；无命中返回明确标记。

用包含虚构参数的样本文档验证答案来自检索，而不是模型已有知识。

```python
# 这是受控测试数据，不是关于真实产品的事实。
# 子块只保留摘要；答案所需的具体参数仅存在于父块中。
PARENTS = {
    "aurora_p0": {
        "source": "aurora_test.md",
        "content": "Aurora 是测试系统。默认重试次数为 7 次，等待间隔为 13 秒。",
    }
}
CHILDREN = [
    {
        "parent_id": "aurora_p0",
        "source": "aurora_test.md",
        "content": "Aurora 的重试策略见本节，包括次数与间隔。",
    }
]


@tool
def search_child_chunks(query: str, limit: int = 3) -> str:
    """搜索文档摘要，返回来源和父块 ID。关键词应简短，例如 Aurora。"""
    # 固定样本使用字符串匹配，让检索行为确定、便于验证。
    # 模型可以请求检索，但匹配、截取和结果构造由程序负责。
    if limit < 1:
        return "INVALID_LIMIT: limit 必须大于等于 1"
    hits = [c for c in CHILDREN if query.strip().casefold() in c["content"].casefold()]
    if not query.strip() or not hits:
        return "NO_RELEVANT_CHUNKS"
    return "\n\n".join(
        f"Parent ID: {c['parent_id']}\nFile Name: {c['source']}\nContent: {c['content']}"
        for c in hits[:limit]
    )


@tool
def retrieve_parent_chunks(parent_id: str) -> str:
    """用搜索返回的父块 ID 读取完整上下文；不要猜测 ID 或重复读取。"""
    parent = PARENTS.get(parent_id)
    if parent is None:
        return "NO_PARENT_DOCUMENT"
    # 和搜索结果保持相同的标签，让来源和父块关系可追踪。
    return (
        f"Parent ID: {parent_id}\nFile Name: {parent['source']}\n"
        f"Content: {parent['content']}"
    )
```

#### 验证与判断

直接调用两个工具：搜索 `Aurora` 必须返回 `aurora_p0`；读取该父块必须得到 7 次、13 秒；搜索不存在的关键词和读取不存在的 ID 必须得到约定标记。

后续替换后端时，优先保持这两个工具的名称、参数和来源字段稳定。当前仅验证父子读取协议，实际分块与索引属于第 5 阶段。

### 1.3 将工具与证据约束交给模型

#### 需要做什么

为检索 Agent 写一个简洁的决策约束：先搜索，摘要不足时读取父块，证据足够后回答。明确无证据时的行为，避免模型用一般知识填充文档答案。

```python
TOOLS = [search_child_chunks, retrieve_parent_chunks]
TOOLS_BY_NAME = {item.name: item for item in TOOLS}

SYSTEM_PROMPT = """你是文档检索助手，使用简体中文回答。
必须先搜索文档。搜索时优先使用短关键词，例如系统名称。
摘要没有足够事实时，使用搜索返回的 parent_id 读取完整父块。
不要重复读取同一父块。证据足够后停止调用工具，回答并标明文件名。
只依据工具返回的文档证据；没有证据时说明无法从文档确认。
工具返回错误时，不把错误文本当成文档事实。
"""


def build_agent_model(llm):
    # 工具注册与提示词属于 Agent 配置，和供应商连接参数分开。
    # 保持自动工具选择，以便观察模型实际决策，不强制预设调用路径。

```

#### 验证与判断

验收以调用轨迹为准，不能仅看最终答案是否像正确答案。Prompt 是行为要求，不是程序保证；程序级预算由 1.6 实现，重复读取的硬约束后续阶段再实现。

### 1.4 明确一次任务的消息状态

#### 需要做什么

每次独立问题创建新的消息列表，保存模型原始响应。先隔离单任务状态，避免在尚未设计会话记忆前把旧证据混入新问题。

```python
def start_messages(question: str):
    # 这里只保存当前任务的输入；跨问题会话记忆在第 6 阶段设计。
    return [SystemMessage(content=SYSTEM_PROMPT), HumanMessage(content=question)]


def request_model(agent_model, messages):
    response = agent_model.invoke(messages)
    # AIMessage 中的工具请求必须保留，之后才能与 ToolMessage 配对。
    # 迁移到 LangGraph 时，这部分成为模型节点的消息更新。
    messages.append(response)
    return response
```

#### 验证与判断

第一轮应产生搜索请求；第二轮可能产生父块读取请求；最后一轮没有 `tool_calls`。若模型直接回答，记录为行为失败，而不是把正确数字当作检索成功。

此阶段用消息历史承载证据，不额外维护一份相同内容的上下文缓存。

### 1.5 实现工具分发与结果回传

#### 需要做什么

执行模型返回的全部工具请求，逐个回传配对结果。工具参数错误应转成可见的失败结果，让模型有机会调整；网络或模型接口故障则直接暴露，不伪装成检索无命中。

```python
def execute_tools(calls, messages):
    for call in calls:
        selected = TOOLS_BY_NAME.get(call["name"])
        if selected is None:
            # 工具不在注册表里时，不运行任何模型生成的代码。
            output = f"UNKNOWN_TOOL: {call['name']}"
        else:
            try:
                output = selected.invoke(call["args"])
            except (ValueError, TypeError) as exc:
                # 包括工具输入校验错误；明确返回错误，不当成正常证据。
                output = f"TOOL_INPUT_ERROR: {exc}"

        # 一条响应可能包含多个工具请求，每个都需要对应结果。
        # 不删除请求，不改写 id，不用用户消息冒充工具结果。
        messages.append(ToolMessage(content=str(output), tool_call_id=call["id"]))
        print("工具：", call["name"], "参数：", call["args"], "结果：", output)
```

#### 验证与判断

检查每个调用 ID 都有一条对应 ToolMessage。用人工构造的工具调用分别测试合法参数、错误类型和未知工具。此执行器处理的是明确的注册工具，不支持动态执行代码。

### 1.6 实现受限循环并验证证据链

#### 需要做什么

完成“模型决策 → 工具执行 → 再决策”的循环。分别限制模型轮数和累计工具调用数；结束时区分正常回答与预算耗尽。

```python
def run_agent(question: str, agent_model, max_rounds: int = 6, max_tool_calls: int = 8):
    messages = start_messages(question)
    tool_count = 0

    for round_index in range(max_rounds):
        print(f"模型轮次：{round_index + 1}")
        response = request_model(agent_model, messages)
        calls = response.tool_calls

        if not calls:
            # 没有后续工具请求，正常完成；保留轨迹用于检查证据来源。
            return {"status": "completed", "answer": response.content, "messages": messages}

        if tool_count + len(calls) > max_tool_calls:
            # 整批拒绝，避免只执行部分请求导致消息配对不完整。
            # 这里直接退出，不携带尚未配对的消息再次请求模型。
            return {"status": "tool_budget_exhausted", "answer": "", "messages": messages}

        execute_tools(calls, messages)
        tool_count += len(calls)

    # 循环耗尽属于未完成，不能把最后一次工具请求冒充答案。
    return {"status": "round_budget_exhausted", "answer": "", "messages": messages}


if __name__ == "__main__":
    # 模型仅在实际运行时创建，便于导入工具进行离线验证。
    agent_model = build_agent_model(build_llm())
    result = run_agent("Aurora 默认重试多少次，间隔多久？", agent_model)
    print("结束状态：", result["status"])
    print("最终回答：", result["answer"])
```

| 模型轮数 | 设置 max_rounds=1，第一轮返回工具请求 | 执行该轮工具后状态为 round_budget_exhausted |

## 第 2 阶段：文档处理与检索后端

### 本阶段交付与模块边界

你已经有 `agent_core.py`。现在自行新增 `retrieval_backend.py`，把下面六段 Python 代码按顺序写入该文件。目标是先独立证明真实文档能够被正确检索，再让模型消费检索结果。

此阶段不修改 `agent_core.py` 的固定父子工具：平面分块还没有真实的父块映射，不能为了接入而随意填造 `parent_id`。第 3 阶段使用这个后端建立基础 RAG，第 5 阶段再替换 Agent 的父子工具。

采用以下明确取舍：

- 只做 dense 检索，与第 5 阶段的混合检索形成对照。
- 使用本机已有的 `quentinz/bge-large-zh-v1.5:latest`，通过 OllamaEmbeddings 生成中文向量。聊天模型不用于向量化。
- 输入限定为 `docs/` 下的 PDF，保留相对于该目录的路径，避免不同目录的同名文件混淆。
- Markdown 按文档整体生成，因此暂不声称有精确页码定位；保留原文件、Markdown 文件和 chunk ID。
- Milvus 运行在 Docker 中；Python 从宿主机连接映射端口 19530，数据持久化由容器卷负责。重建期间不要并发查询这个测试集合。
- 当前索引是专用集合的全量重建，不实现增量同步。重复导入后集合数量应稳定，删除源文件后重建也会移除旧记录。

#### 需要做什么

import argparse
import os
import hashlib
import json
import uuid
from pathlib import Path

import pymupdf4llm
from langchain_core.documents import Document
from dotenv import load_dotenv
from langchain_ollama import OllamaEmbeddings
from langchain_text_splitters import RecursiveCharacterTextSplitter
from pymilvus import MilvusClient, DataType

# 使用独立集合，后续重建只影响此阶段的索引。

# 本阶段以字符计量，不把 300 字符误当成 300 token。
# 索引签名同时记录模型和切分参数，避免查询悄悄使用另一套配置。
INDEX_SIGNATURE = json.dumps(
    {"embedding": EMBEDDING_MODEL, "chunk_size": CHUNK_SIZE,
     "chunk_overlap": CHUNK_OVERLAP, "pipeline": "stage2-v1"},

### 2.2 转换 PDF，保留可检查的 Markdown

#### 需要做什么

将每份 PDF 转换成 Markdown 并保存，构造文档对象。先观察转换质量，再讨论检索参数；扫描件的 OCR 不属于当前实现范围。

```python
def load_pdf_documents() -> list[Document]:
    pdf_paths = sorted(p for p in DOCS_DIR.rglob("*")
                        if p.is_file() and p.suffix.lower() == ".pdf")
    if not pdf_paths:
        # 没有输入就退出，不能拿一个空输入去重建已有集合。
        raise ValueError(f"请先向 {DOCS_DIR} 放入文字可选中的 PDF。")

    documents = []
    for pdf_path in pdf_paths:
        relative = pdf_path.relative_to(DOCS_DIR)
        # 保留 .pdf 再追加 .md，避免 A.pdf 和 A.PDF 转换产物同名。
        markdown_path = MARKDOWN_DIR / relative.parent / (relative.name + ".md")
        markdown_path.parent.mkdir(parents=True, exist_ok=True)

        # 每次重建都重新转换，避免源 PDF 修改后仍读取旧 Markdown。
        # ignore_images 适合此阶段的文字检索，不代表支持图表理解。
        markdown = pymupdf4llm.to_markdown(str(pdf_path), ignore_images=True)
        if not markdown.strip():
            raise ValueError(f"转换结果为空，请检查是否为扫描件：{relative}")
        markdown_path.write_text(markdown, encoding="utf-8")

        documents.append(Document(
            page_content=markdown,
            metadata={
                "source": relative.as_posix(),
                "markdown_source": markdown_path.relative_to(BASE_DIR).as_posix(),
                # 原文件摘要用于核对来源版本，不承担增量索引功能。
                "source_sha256": hashlib.sha256(pdf_path.read_bytes()).hexdigest(),
            },
        ))
    return documents
```

#### 验证与判断

检查至少一份 Markdown 的标题、正文顺序、表格和关键数字。尤其关注双栏 PDF 的阅读顺序。非空结果仅证明有文本，不能证明转换正确。

本次索引只使用当前 PDF 清单返回的文档，不遍历 Markdown 目录。因此源文件删除后，即使旧 Markdown 留在磁盘，也不会重新进入索引。

### 2.3 切分文档，建立稳定的 chunk 标识

#### 需要做什么

先使用单层字符分块建立检索基线。继承文档元数据，再补上块序号和 ID；相同输入与参数应产生相同 ID。

```python
def split_documents(documents: list[Document]) -> list[Document]:
    splitter = RecursiveCharacterTextSplitter(
        chunk_size=CHUNK_SIZE,
        chunk_overlap=CHUNK_OVERLAP,
        # 优先保留段落和句子；末尾空串允许必要时按字符继续切分。
        separators=["\n\n", "\n", "。", "！", "？", " ", ""],
    )
    chunks = []
    for document in documents:
        parts = splitter.split_documents([document])
        for index, chunk in enumerate(parts):
            # 路径、原文件版本、切分配置及序号共同确定身份。
            # 参数改变意味着索引版本改变，不复用旧块的身份。
            identity = json.dumps(
                [chunk.metadata["source"], chunk.metadata["source_sha256"],
                 INDEX_SIGNATURE, index], ensure_ascii=False,
            )
            chunk.metadata.update({
                "chunk_index": index,
                # Milvus 点 ID 使用合法 UUID，而不是任意字符串拼接。
                "chunk_id": str(uuid.uuid5(uuid.NAMESPACE_URL, identity)),
                "index_signature": INDEX_SIGNATURE,
            })
            chunks.append(chunk)
    if not chunks:
        raise ValueError("未生成可索引的文本块。")
    return chunks
```

#### 验证与判断

打印块数、长度分布、前两块内容和 metadata。重复切分同一批文档，chunk ID 应相同；两个子目录里的同名 PDF 应有不同 ID。

这里的 overlap 是目标重叠量，实际分隔与合并可能使重叠少于 60 字符，不应写测试强求每对相邻块恰好重叠 60 字符。

### 2.4 初始化 Embedding 与 Milvus，并执行全量重建

#### 需要做什么

用实际向量长度创建 Milvus schema。先转换、切分并生成全部向量，确认上游正常后才替换本阶段专用集合；转换或模型下载失败时不要先删除旧索引。

```python
def build_embeddings():
    # 通过本机 Ollama 服务向量化，不连接云端 API。
    # BGE 模型上下文有限，300 字符只是初始值，仍需检查长英文和代码块。
    return OllamaEmbeddings(model=EMBEDDING_MODEL, base_url=OLLAMA_URL)


def open_milvus():
    # 宿主机连接 Docker 暴露的端口；若 Python 也进容器，地址需改为服务名。
    # 未开启鉴权时不传 token；启用鉴权时使用实际凭证。
    args = {"uri": MILVUS_URI}
    if MILVUS_TOKEN:
        args["token"] = MILVUS_TOKEN
    return MilvusClient(**args)


def rebuild_index(chunks: list[Document], embeddings):
    if not chunks:
        raise ValueError("拒绝用空文档重建索引。")
    # 先完成向量化，模型服务失败时不会提前删除旧集合。
    vectors = embeddings.embed_documents([c.page_content for c in chunks])
    if len(vectors) != len(chunks) or not vectors or not vectors[0]:
        raise ValueError("向量数量或维度异常。")
    dimension = len(vectors[0])
    if any(len(v) != dimension for v in vectors):
        raise ValueError("同批向量维度不一致。")

    client = open_milvus()
    try:
        # 只重建本阶段专用集合；这是全量替换，不是事务切换。
        schema = MilvusClient.create_schema(auto_id=False, enable_dynamic_field=False)
        schema.add_field("id", DataType.VARCHAR, is_primary=True, max_length=36)
        schema.add_field("vector", DataType.FLOAT_VECTOR, dim=dimension)
        schema.add_field("page_content", DataType.VARCHAR, max_length=65535)
        schema.add_field("metadata", DataType.JSON)
        indexes = client.prepare_index_params()
        # 小语料使用 FLAT 精确检索，先排除近似索引召回误差。
        indexes.add_index(field_name="vector", index_type="FLAT", metric_type="COSINE")
        if client.has_collection(COLLECTION):
            client.drop_collection(COLLECTION)
        client.create_collection(collection_name=COLLECTION, schema=schema,
                                 index_params=indexes, consistency_level="Strong")
        result = client.insert(collection_name=COLLECTION, data=[
            {"id": chunk.metadata["chunk_id"], "vector": vector,
             "page_content": chunk.page_content, "metadata": chunk.metadata}
            for chunk, vector in zip(chunks, vectors)
        ])
        client.flush(collection_name=COLLECTION)
        client.load_collection(collection_name=COLLECTION)
        print("索引完成：", result["insert_count"], "块")
    finally:
        # 关闭客户端连接，不停止 Docker 服务，也不删除持久化数据。
        client.close()
```

#### 验证与判断

集合点数应等于 chunk 数。重复重建后数量不应翻倍。删除一个源 PDF 后重建，该文档的记录应消失。

这是全量替换，不是事务更新：删除集合之后如果写入失败，需要重新运行索引命令恢复。只允许它操作当前专用集合，不拿此策略直接更新正式服务数据。

### 2.5 独立查询，先观察证据和分数

#### 需要做什么

查询直接返回 `Document + score`，不调用聊天模型。检查索引签名，打印来源和内容，让检索失败不会被生成回答掩盖。

```python
def search_documents(query: str, embeddings, k: int = 3):
    if not query.strip() or k < 1:
        raise ValueError("query 不能为空，k 必须大于等于 1。")
    client = open_milvus()
    try:
        if not client.has_collection(COLLECTION):
            raise ValueError("索引不存在，请先运行 index 命令。")
        client.load_collection(collection_name=COLLECTION)
        rows = client.query(collection_name=COLLECTION, filter="", limit=1,
                            output_fields=["metadata"], consistency_level="Strong")
        if not rows:
            raise ValueError("索引为空，请重新建立索引。")
        if rows[0]["metadata"].get("index_signature") != INDEX_SIGNATURE:
            raise ValueError("索引配置已改变，请使用当前配置重新建立索引。")
        vector = embeddings.embed_query(query)
        hits = client.search(
            collection_name=COLLECTION, data=[vector], anns_field="vector", limit=k,
            search_params={"metric_type": "COSINE", "params": {}},
            output_fields=["page_content", "metadata"], consistency_level="Strong",
        )
        # 保持后端对外接口为 Document + score，后续 RAG 不依赖 Milvus 返回格式。
        # COSINE 下字段虽名为 distance，但数值越大越相近，不是正确概率。
        return [(Document(page_content=h["entity"]["page_content"],
                          metadata=h["entity"]["metadata"]), h["distance"])
                for h in hits[0]]
    finally:
        client.close()
```

#### 验证与判断

准备一个原文明确有答案的问题和一个明显超出文档的问题。查看前者是否命中正确段落，后者是否仍被返回“最相近但不相关”的内容。

无阈值的近邻检索通常不会对文档外问题自动返回空列表。后续需用样本校准阈值并评估证据充分性，不能直接复制原项目的阈值作为通用标准。

### 2.6 提供索引与查询入口，验证完整数据流

#### 需要做什么

用两个命令分别重建与检索。查询不应触发重建，也不应调用聊天模型；这样可以独立定位数据处理问题。

```python
def main():
    parser = argparse.ArgumentParser(description="第 2 阶段：文档索引与独立检索")
    subparsers = parser.add_subparsers(dest="command", required=True)
    subparsers.add_parser("index", help="全量重建本阶段专用集合")
    query_parser = subparsers.add_parser("query", help="查询现有索引")
    query_parser.add_argument("question")
    args = parser.parse_args()

    if args.command == "index":
        documents = load_pdf_documents()
        chunks = split_documents(documents)
        print("文档数：", len(documents), "块数：", len(chunks))
        print("首块元数据：", chunks[0].metadata)
        rebuild_index(chunks, build_embeddings())
    else:
        hits = search_documents(args.question, build_embeddings())
        for rank, (document, score) in enumerate(hits, start=1):
            print(f"\n排名：{rank}，分数：{score:.4f}")
            print("来源：", document.metadata["source"])
            print("块 ID：", document.metadata["chunk_id"])
            print(document.page_content)


if __name__ == "__main__":
    main()
```

### 第 2 阶段验收矩阵

| 检查 | 操作 | 通过条件 |
| --- | --- | --- |
| 转换正确性 | 对照 PDF 查看 Markdown | 关键段落、数字和顺序正确，转换缺陷有记录 |
| 来源可追溯 | 检查检索结果 metadata | 能定位输入 PDF、转换文件和块 ID；不虚构页码 |

| 配置失配 | 改变模型名或切分参数后只查询 | 拒绝混用，要求重建 |
| 正例检索 | 提出已知答案的问题 | top-k 中出现包含证据的段落 |
